# 4 Model Structure of the Automotive Example
### Objective of the Chapter
The automotive example serves as a consistent teaching model for [*Configuration Modeling*](../../docu-hca/glossary/terms-modeling/#configuration-modeling).
It is deliberately simplified. It is not intended to represent the full technical complexity of a real Vehicle [*Configurator*](../../docu-hca/glossary/terms-infrastructure/#configurator).
Instead, it shows how a real product structure can be represented in submodels, also called [*Component Configuration Models*](../../docu-hca/glossary/terms-modeling/#component-configuration-model),
shortly **Component Models** or **Components**.
It also explains how [*Attributes*](../../docu-hca/glossary/terms-modeling/#attribute)  are assigned and how
[*Rules*](../../docu-hca/glossary/terms-modeling/#configuration-rule) can be formulated both between submodels and within a submodel.<br>

The focus is on the following questions:<br>

- Which parts of a product are described as separate Component Models?
- Which characteristics are modeled as Configuration Attributes?
- Which information belongs in the main model Car, and which information belongs in submodels such as Engine, Transmission, or Wheel?
- How are shared technical specifications, such as a uniform rim size, used across different [*Configuration Models*](../../docu-hca/glossary/terms-modeling/#configuration-model)?
